# 夯实地基 Guide

## Purpose

Use this method when requirements, implementation, and learned project knowledge start drifting apart.

This method can be referred to by its working name:

- `夯实地基`

## Core Rule

Do not keep knowledge in a separate floating pile.

Bind it directly to requirement points through stable `KB-*` ids.

## Split Of Responsibilities

### Requirement Docs

Carry:

- goal
- status
- scope
- verification targets
- open questions
- links to `KB-*`

### KB Docs

Carry:

- reusable verified conclusions
- implementation-relevant constraints
- source evidence

### Experiment Docs

Carry:

- provisional hypotheses
- test setup
- captured evidence
- promotion decisions

## Promotion Rule

Only promote a conclusion into `KB-*` when it is stable enough to change future implementation decisions.
