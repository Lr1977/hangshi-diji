# Contributing

## Scope

This repository is a method kit, not a product runtime.

## Rules

- keep changes narrow
- separate core protocol from project-specific examples
- add evidence when promoting a conclusion
- do not put secrets or private project state in commits
- keep deprecated material explicitly marked

## Workflow

1. write a plan
2. implement narrowly
3. verify the changed path
4. audit against the plan
5. update the relevant docs

## Pull Requests

Prefer small, scoped PRs:

- one protocol change
- one sample change
- one migration note

## Versioning

Use semantic-ish release tags for the kit:

- `v0.x` for structure and process growth
- `v1.0` only after the core layers stabilize
